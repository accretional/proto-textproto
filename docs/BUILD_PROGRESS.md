# BUILD_PROGRESS.md

## Overview

proto-textproto provides a gluon v2 EBNF grammar for the Protocol Buffers Text Format (textproto) language, generates proto definitions from it, and includes a parser/validator tool for textproto files.

## Pipeline Steps

1. **EBNF Grammar** (`textproto.ebnf`) — Hand-written from the [textproto spec](temp/textproto_spec.html)
2. **Parse EBNF** — `metaparser.ParseEBNF()` → GrammarDescriptor (84 rules)
3. **Convert to AST** — `compiler.GrammarToAST()` → ASTDescriptor
4. **Compile to proto** — `compiler.Compile()` → FileDescriptorProto (112 messages)
5. **Serialize proto** — Custom serializer → `proto/textproto.proto`
6. **Compile Go stubs** — `protoc --go_out` → `proto/gen/textproto.pb.go`
7. **Parse textproto files** — `metaparser.ParseCST()` with grammar + input → AST validation

## Grammar Design

### Syntactic vs Lexical Convention

The grammar uses gluon v2's `DefaultIsLexical` behavior:
- **Uppercase rules** (e.g., `Message`, `Field`, `ScalarValue`) are **syntactic** — whitespace is automatically skipped between elements
- **Lowercase rules** (e.g., `ident`, `string_literal`, `dec_lit`) are **lexical** — no whitespace skipping within tokens

This matches the textproto spec's distinction between syntactic structure (fields, values, lists) and lexical tokens (identifiers, strings, numbers).

### Comment Handling

Textproto uses `#` for line comments. Gluon's parser handles `//`, `/* */`, and `(* *)` but NOT `#`. The parser tool strips `#` comments via a preprocessor before passing input to `ParseCST`. The comment stripper is string-aware (doesn't strip `#` inside quoted strings).

### String Concatenation

The textproto spec allows multiple quoted strings on successive lines to concatenate:
```
field: "hello"
       "world"
```

The grammar handles this via `StringVal = string_literal , { string_literal }` at the syntactic level, so whitespace between string literals is automatically skipped.

## Misalignments and Deviations from Spec

### 1. Unescaped Control Characters in Strings

The spec allows all non-NUL characters (U+0001–U+10FFFF) as unescaped string content, minus the quote, newline, and backslash. The grammar only supports:
- Tab (U+0009) — as a literal tab character
- Space to U+10FFFF (via ranges)

Other control characters (VT U+000B, FF U+000C, CR U+000D, etc.) in strings must use escape sequences. This is a pragmatic choice — embedding control characters in EBNF ranges requires literal bytes that are hard to maintain.

### 2. URL Prefix in Any Fields

The spec defines `UrlPrefix = url_char, { url_char | "/" }`, allowing `/` inside the URL prefix. This creates a greedy matching problem — the parser would consume the separator `/` between the URL prefix and type name.

The grammar uses `url_prefix = url_char , { url_char }` (without `/` in the repetition), which handles the common case: `[type.googleapis.com/com.example.Type]`. URLs with internal path segments (e.g., `[host/path/segment/Type]`) would not parse correctly. In practice, Any URLs follow the `authority/TypeName` pattern.

### 3. No Whitespace Inside Extension/Any Brackets

The spec notes: "No whitespace/comments within brackets (serializers must not write any; parsers should skip)." Since extension_name and any_name are lexical rules (lowercase), whitespace is NOT skipped between `[`, the type name, and `]`. This matches the serializer convention.

### 4. Unicode Proto Source

The `unicode/ascii.proto` and `unicode/utf_8.proto` files are copied from gluon with `go_package` updated to `github.com/accretional/proto-textproto/proto/gen/unicode`. This follows the same pattern as proto-json.

### 5. Proto Files are 100% Generated

`proto/textproto.proto` is entirely generated by `lang/metaparser` using gluon v2's compiler. No hand-written proto files.

## Build Scripts

All scripts are idempotent and chain: `LET_IT_RIP.sh` → `test.sh` → `build.sh` → `setup.sh`.

- **setup.sh**: Checks Go, protoc, protoc-gen-go, gluon v2; runs `go mod tidy`
- **build.sh**: Verifies pre-generated proto files exist; builds `bin/parse`
- **test.sh**: Runs parser against all valid/invalid examples
- **LET_IT_RIP.sh**: Runs full pipeline

Proto files and gRPC stubs are NOT regenerated during build or test.
